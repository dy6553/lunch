# ESP32와 급식실 웹사이트 연결

## 사용할 프로그램

- 센서 1개 거리 측정 확인: [sensor_check](sensor_check/README.md)
- 센서 1개 또는 2개와 웹사이트 연동: `cafeteria_gate/cafeteria_gate.ino` (버전 1.8.0)

개인용 다운로드에는 전송 주소와 이 보드의 장치키가 설정되어 있습니다.
Wi-Fi는 휴대폰 설정 화면에서 입력하므로 `secrets.h`의 아래 두 줄은 비워 두어도 됩니다.

```cpp
#define WIFI_SSID ""
#define WIFI_PASSWORD ""
```

공개 저장소의 `secrets.h.example`에는 실제 장치키가 없습니다.
공개 예제를 직접 사용하면 서버에 등록한 장치키도 설정해야 합니다.
장치키가 들어 있는 개인용 ZIP과 `secrets.h`는 공개하지 않습니다.

## 휴대폰으로 Wi-Fi 설정·변경

1. 이 버전을 보드에 한 번 업로드합니다. 기존 펌웨어는 사이트만 수정해도 자동 업데이트되지 않습니다.
2. 처음 켜면 휴대폰 Wi-Fi 목록에서 **ESP32 Setup**을 선택하고 비밀번호 **lunchsetup**을 입력합니다.
3. 설정 화면이 자동으로 열리지 않으면 브라우저에서 **http://192.168.4.1**을 엽니다. HTTPS가 아닌 HTTP입니다.
4. 인터넷에 연결할 **2.4GHz Wi-Fi 이름과 비밀번호**를 입력하고 **연결하고 저장**을 누릅니다.
5. 연결 확인에 최대 30초가 걸립니다. 성공한 정보만 보드에 저장하고 설정용 Wi-Fi는 약 15초 후 종료합니다.
6. 휴대폰을 원래 Wi-Fi나 모바일 데이터에 다시 연결하고 급식 사이트를 엽니다.

`ESP32 Setup`은 설정용이므로 휴대폰에서 인터넷 없음으로 표시되어도 연결을 유지합니다.
화면이 안 열리면 모바일 데이터를 잠시 끄고 위 주소를 직접 입력합니다.
AP 비밀번호는 `config.h`의 `WIFI_SETUP_PASSWORD`에서 바꿀 수 있습니다.

**이미 Wi-Fi에 연결돼 있으면 링크로 바로 변경할 수 있습니다.**

1. 휴대폰이나 컴퓨터를 **보드와 같은 Wi-Fi**에 연결합니다.
2. 브라우저 주소창에 **http://esp32.local**을 입력합니다.
3. 로그인 창에서 아이디 **admin**, 비밀번호 **lunchsetup**을 입력합니다.
4. 새 Wi-Fi 정보를 입력하고 저장합니다. 컴퓨터로 다시 업로드할 필요가 없습니다.

설정 화면은 보드 내부에 있으므로 모바일 데이터만 사용하는 상태나 다른 장소에서는 열리지 않습니다.
`esp32.local`이 열리지 않으면 시리얼 모니터의 `WIFI SETTINGS`에 출력된 **http://보드IP주소**로 접속합니다.
공유기에서 기기 간 통신을 막는 게스트 Wi-Fi도 로컬 주소 접속이 안 될 수 있습니다.
LAN 로그인 비밀번호도 `config.h`의 `WIFI_SETUP_PASSWORD`를 사용합니다.
Wi-Fi를 변경하면 휴대폰도 새 Wi-Fi에 연결한 뒤 같은 링크를 다시 엽니다.
설정 화면만 여는 동안에는 센서 측정과 기존 업로드가 계속됩니다.
실제로 다른 Wi-Fi로 전환하는 동안에는 전송이 잠시 끊길 수 있습니다.
새 Wi-Fi 연결에 실패하면 기존 저장 정보를 지키고 기존 Wi-Fi로 재연결합니다. 설정 화면은 재입력을 위해 유지합니다.
기존 연결을 쓰려면 **설정용 Wi-Fi 끄기**를 누릅니다. 이 버튼으로 설정용 AP만 닫고 링크 접속은 계속 사용할 수 있습니다.

링크를 열 수 없으면 보드가 켜진 상태에서 **BOOT 버튼을 3초 누르고 놓아** `ESP32 Setup`을 다시 열 수도 있습니다.
전원을 켜거나 EN/RST를 누르는 동안 BOOT을 누르면 업로드 모드로 들어갈 수 있으므로, 부팅한 뒤 누릅니다.

전원을 껐다 켜면 저장한 Wi-Fi에 자동 연결합니다. 연결이 30초 이상 끊기면 설정용 Wi-Fi를 자동으로 다시 엽니다.
보드에 저장한 정보가 `secrets.h`의 선택적 기본값보다 우선합니다. Wi-Fi 비밀번호나 사이트 장치키를 설정 화면에 표시하지 않습니다.

## 센서 개수 선택

`cafeteria_gate/config.h`의 기본값은 **`SENSOR_COUNT 1`**입니다. 센서 1개는 VIN/GND/SDA/SCL 네 선만 연결합니다.
안정적으로 감지된 사람이 감지 구역을 벗어나면 1명으로 집계합니다. 방향 구분이 없으므로 입장 전용 통로에 설치하세요.
센서 2개를 사용하면 `SENSOR_COUNT 2`로 바꾸고 아래 표처럼 XSHUT도 연결합니다.
VL53L0X와 VL53L1X를 자동 인식하며, 센서 모듈의 전원 지원 범위를 확인해야 합니다.

## 배선: ESP32 1개 + VL53L1X 2개

USB 전원을 뽑고 배선합니다. 센서 모듈의 3.3V VIN 입력 지원을 확인하고,
기판에 적힌 핀 이름을 기준으로 연결합니다.

| ESP32 핀 | 센서 A | 센서 B |
|---|---|---|
| 3V3 | VIN | VIN |
| GND | GND | GND |
| G21 / GPIO21 | SDA | SDA |
| G22 / GPIO22 | SCL | SCL |
| G18 / GPIO18 | XSHUT | 연결 안 함 |
| G19 / GPIO19 | 연결 안 함 | XSHUT |

두 센서의 GPIO1은 연결하지 않습니다.
XSHUT은 LOW와 입력(고임피던스) 모드를 전환해 제어합니다.
두 센서를 순서대로 초기화하고 I2C 주소를 0x30, 0x31로 나눕니다.
사진과 같은 캐리어의 XSHUT 풀업을 사용하며, 3.3V HIGH를 강제로 출력하지 않습니다.
처음에는 짧은 배선으로 테스트합니다. 긴 I2C 배선은 별도 버스 연장기 등이 필요할 수 있습니다.

## Arduino IDE에서 업로드

1. 보드 매니저에서 `esp32 by Espressif Systems`를 설치합니다.
2. 라이브러리 매니저에서 `VL53L1X by Pololu`와 `VL53L0X by Pololu`를 설치합니다.
3. 개인용 ZIP을 풀고 폴더와 같은 이름인 `cafeteria_gate.ino`를 엽니다.
   `ca_cert.h`, `config.h`, `wifi_setup.h`, `secrets.h`를 같은 폴더에 둡니다.
4. 보드는 `ESP32 Dev Module`, 연결된 USB 포트를 선택합니다.
5. Wi-Fi 두 값은 빈 문자열로 두어도 됩니다. 업로드 후 휴대폰에서 설정합니다.
6. 시리얼 모니터를 `115200 baud`로 엽니다. 출력이 없으면 EN/RST를 누릅니다.
   업로드가 연결 대기에서 멈추면 BOOT을 누른 채 업로드를 시작하고 쓰기 진행 시 놓습니다.

Wi-Fi는 인터넷 연결이 가능한 **2.4GHz, 일반 비밀번호 방식**을 사용합니다.
학교 로그인 웹페이지나 기업용 계정 인증이 필요한 네트워크는 이 설정만으로 연결되지 않습니다.
처음에는 2.4GHz 휴대폰 핫스팟으로 확인할 수 있습니다.
인터넷 HTTPS(443)와 시간 동기화 NTP(UDP 123)가 허용되어야 합니다.

## 정상 출력

```text
WIFI SETUP READY: join ESP32 Setup, then open http://192.168.4.1/
SENSORS OK
WIFI SAVED: setup Wi-Fi closes in 15 seconds.
WIFI OK; synchronizing time for HTTPS...
SERVER OK: single-sensor passage counting enabled.
HEARTBEAT HTTP 200
SENSOR A: 420 mm
UPLOAD A #1 HTTP 200
```

- `WIFI SETUP READY`: 휴대폰으로 `ESP32 Setup`에 연결해 Wi-Fi를 입력합니다.
- `WIFI SETUP FAILED`: 입력한 Wi-Fi에 연결하지 못했습니다. 설정 화면에서 다시 입력합니다. 기존 저장 정보는 유지됩니다.
- `WIFI SAVE FAILED`: 연결은 되었지만 보드 저장에 실패했습니다. 설정 화면에서 저장을 다시 시도합니다.
- `WIFI CONNECTING`: Wi-Fi 이름·비밀번호·2.4GHz 사용 여부를 확인합니다.
- `SENSOR INIT FAILED`: 설정한 센서 개수와 배선을 확인합니다. 센서 2개 모드면 XSHUT도 확인합니다. 자동 재시도합니다.
- `WAITING FOR TIME`: NTP가 차단되지 않았는지 확인합니다. 시간 동기화 후 인증서 검증을 진행합니다.
- `SERVER CHECK HTTP 401`: 장치키가 서버와 다르거나 등록되지 않았습니다.
- `SERVER CHECK HTTP 503`: 서버의 데이터베이스 설정·접근 권한을 확인합니다.
- 음수 HTTP 코드: 인터넷·DNS·HTTPS 인증서 또는 연결 시간을 확인합니다.
- `SITE CLOSED` / `SITE PAUSED`: 연결은 정상이나 급식 운영이 종료/중지 상태입니다.
  학생 화면에 안내하려면 관리자 화면의 **배식 운영 상태**를 배식 중으로 설정합니다.
  인원 증가 여부는 별도의 **센서 인원 집계 반영** 설정으로 제어합니다.
- `QUEUE FULL` / `EVENT EXPIRED`: 네트워크 중단으로 일부 이벤트가 누락됐습니다.
  연결을 복구한 뒤 관리자가 실제 인원과 표시값을 맞춰 주세요.

## 사이트 표시와 집계 방식

연결키 검증과 데이터베이스 읽기 확인이 끝나면 센서 이벤트를 자동 전송합니다.
센서 측정은 인터넷 전송과 다른 태스크에서 계속 수행합니다.
20초마다 상태 확인 신호를 보내며, 사이트는 약 90초 이상 신호가 없으면 연결 끊김으로 안내합니다.
데이터베이스 연결 상태와 실제 보드·센서 연결 상태를 구분합니다.

관리자의 **급식 운영 상태는 자동으로 바꾸지 않습니다.**
- **센서 인원 집계 반영**을 켜면 배식 전·일시 중지 중에도 통과 인원을 누적할 수 있습니다.
- 집계를 꺼도 연결 상태는 계속 갱신하며, 꺼진 동안의 이벤트는 소급 반영하지 않습니다.
- 운영 중 + 센서 준비 완료: 현재 대기 인원과 예상 대기 표시
- 센서 미연결/초기화 실패: 대기 정보 보류, 연결·배선 안내
- 운영 종료/일시 중지: 기존 운영 안내 유지

센서 1개 모드는 감지 후 감지 해제된 통과를 1명으로 집계합니다. 웹에도 센서 1개 집계임을 표시합니다.
센서 2개 모드는 두 감지 구역을 통로 진행 방향으로 앞뒤 배치합니다. A 다음 B가 감지되면 줄 진입입니다.
B 다음 A는 역방향 기록이며, 이 프로젝트에서는 대기 인원을 직접 차감하지 않습니다.
인원 감소는 기존의 배식 속도에 따른 추정 계산을 유지합니다.
인원 증가는 배식 운영 상태와 별도인 센서 집계 설정을 따릅니다. 자동 감소는 배식 중에만 적용합니다.
새 설정을 저장한 적이 없는 기존 문서는 종전처럼 운영 중일 때만 집계합니다.

센서 2개 모드의 유효한 A/B 통과 간격은 100~8000ms입니다. 보드 부팅 세션과 캡처 시각을 사용하므로
전송 지연이 통과 간격으로 오인되지 않으며, 같은 이벤트 재전송은 중복 집계하지 않습니다.
네트워크 준비 전 감지는 로컬 로그만 출력합니다. 전송 대기 30초를 넘긴 이벤트는
오래된 인원으로 뒤늦게 집계하지 않습니다. 재부팅 시 메모리 큐는 비워집니다.

기본 진입 기준은 900mm 미만, 감지 해제 기준은 1050mm 이상, 각각 연속 3회입니다.
실제 설치 위치에서 빈 통로 배경과 사람의 거리값을 측정해 이 두 값을 보정합니다.
처음에는 사람이 한 명씩 지나가게 시험합니다. 나란히 걷거나 겹쳐 지나가면 이 센서 구성은 오차가 발생할 수 있습니다.

## 검증 범위

- 실제 ESP32 컴파일러로 `esp32dev`, Arduino-ESP32 2.0.17, Pololu VL53L0X/VL53L1X 빌드 확인
- `python scripts/firmware-wifi-setup.test.py`: 첫 설정, LAN 인증·변경, 저장 후 재부팅, 실패 시 복구, 저장 실패·재시도, 시간 오버플로 테스트
- 서버 인증, 상태 확인 신호, 재전송 중복 방지, 세션 분리, 지연 이벤트, 트랜잭션 충돌 테스트
- HTTPS 인증서·호스트 이름 검증 사용(ISRG와 Google Trust Services 공개 루트)
- 실제 보드 업로드·학교 Wi-Fi·설치 위치에서의 통과 정확도는 현장 시험 필요


## 1.6.0 안정화

감지 구역이 0.5초 연속으로 비워지면 통과를 확정합니다. Wi-Fi 연결이 끊겨도 최대 128건을 RAM에 보관하고 5분 이내에 재전송합니다. 전원을 끄거나 버퍼가 넘치면 복구할 수 없습니다. 관리자 화면에서 펌웨어 버전, Wi-Fi 신호, 전송 대기 및 누락 건수를 확인하세요. 기존 secrets.h와 센서 개수 설정을 유지하고 수정 펌웨어를 다시 업로드해야 합니다.


## 웹에서 감지 거리 변경 (1.8.0)

센서 1개 모드에서는 보드가 거리값과 측정 상태만 보내고 웹 서버에서 사람 통과와 인원을 판단합니다. 관리자 화면의 운영 설정에서 감지 거리(cm)를 바꾸고 저장하면 다음 거리값부터 새 기준으로 판단합니다. 기본값은 150cm, 범위는 10~200cm이고 비워짐 기준은 감지 거리보다 15cm 멀게 설정됩니다. 센서 앞이 0.5초 연속으로 비워지면 통과가 확정됩니다. 최초 1.8.0 업로드 이후 거리 변경에는 보드 재업로드가 필요 없습니다.
